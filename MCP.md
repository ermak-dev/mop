# mop-mcp

MCP-сервер пула: канал сообщений слейвам и управление их job'ами. Замена
встроенному `SendMessage`/`ListAgents` там, где встроенный не достаёт.

Реализация — `bin/mop-mcp`, протокол канала — [CHANNEL.md](CHANNEL.md).

## Зачем, если есть встроенный SendMessage

1. **Он не видит пул.** Встроенный механизм адресует in-process агентов,
   тиммейтов, сессии *этой машины* и облачные/bridge-сессии. Слейвы живут на
   `mirror` и `gamer` — их сокеты недостижимы снаружи хоста, и сегодня мастер
   достаёт их через мост claude.ai. Мост умирает ровно тогда, когда протухает
   логин, — тот самый случай, который `doctor` ловит отдельной веткой. Здесь
   доставка идёт через Nomad и протухший логин переживает.
2. **Адресат ≠ готовность.** «Сессия есть» — не тот вопрос, который мастер задаёт
   перед диспатчем. Настоящий: свободно ли место, не залипло ли, не кончилась
   ли квота и **не пропадёт ли работа в клоне**. Эта модель живёт в
   `slaves.slave_state`, каналу её взять неоткуда.
3. **Слэш-команды.** Через канал не проходят (сообщение кладётся в очередь с
   `skipSlashCommands`), а `/model` при исчерпанной квоте — штатная операция.

## Топология

```
сессия мастера (управляющая машина)
   └─ stdio ─> mop-mcp ──REST/websocket──> Nomad
                    │                              │
                    │                        alloc exec
                    │                              ↓
                    │                   узел: слейв sl-*
                    │                   cc-socks/<pid>.sock
                    └── инбокс мастера ← фоновый вестник
```

**stdio, не HTTP.** Сервер держит management-токен Nomad; порт с таким токеном
— лишний риск, а мастер и так единственный потребитель. Дать канал самим слейвам
(слейв → слейв, минуя облако) — это отдельный урезанный HTTP-профиль без
управления job'ами, его пока нет.

**Доставка через `alloc exec`.** Сокет сессии — unix-сокет, host-local. Поэтому
отправитель едет НА УЗЕЛ: `mop/session.py` ставится в
`~/.cache/mop/session-<hash>.py` и запускается там. Хэш в имени сам
инвалидирует кэш при правке модуля, узлу ничего доставлять руками не нужно.

**Асинхронные уведомления через инбокс мастера.** MCP умеет только
«запрос-ответ»: сервер не может ничего вбросить в ход модели. Но сервер —
дочерний процесс сессии мастера и знает её сокет (`CLAUDE_CODE_MESSAGING_SOCKET`, с
откатом на обход цепочки родителей). `send(notify_when_idle=true)` поднимает
фоновый поток, который ждёт `peer_idle_notice` от слейва и кладёт результат в
инбокс мастера. Получается настоящий push, без опроса.

## Инструменты

| Инструмент | Аргументы | Аннотация |
|---|---|---|
| `agents` | `project` | readOnly |
| `send` | `to`, `message`, `priority`, `notify_when_idle`, `wait_seconds` | — |
| `tail` | `name`, `lines`, `grep` | readOnly |
| `pool` | — | readOnly |
| `slave` | `action: add\|remove\|restart\|retarget`, `name`, `origin`, `llm` | destructive |
| `doctor` | `fix` | destructive |
| `slash` | `name`, `command` | destructive |
| `login` | — | destructive |

Аннотации не косметика: по ним Claude Code решает, спрашивать ли разрешение.

`send` возвращает **вердикт доставки**, а не факт отправки: «доставлено»,
«НЕ ДОСТАВЛЕНО — причина», «инбокс не слушает». «Отправлено» без этого — то же
самое молчание, от которого мы уходим.

`slash` работает по белому списку (`/model`, `/clear`, `/compact`, `/rc`,
`/status`). Без списка это произвольный ввод в чужую сессию.

`attach` намеренно вне MCP: живой терминал инструментом не отдать.

## Два ограничения, которые стоили отладки

**Лимит URI.** Команда `alloc exec` едет в query-строке URL, а nginx перед
Nomad режет URI примерно на 8 КБ и отвечает 414 ещё до Nomad. Целый
`session.py` — 19 КБ в base64, и первая же отправка отбилась. Отсюда установка
модуля на узел вместо возки в каждом вызове: обычный запрос — короткая команда,
и почти весь бюджет URL достаётся тексту сообщения. `nomad.MAX_EXEC_URL` ловит
перебор явной ошибкой, а не загадочным `WebSocketBadStatusException`.

**Груда мёртвых файлов сессий.** У клона слейва их накапливается много —
каждая умершая сессия оставляет свой (на одном слейве их было 18). Адресовать
по каталогу «самой свежей» нельзя: свежая вполне может быть трупом. Нужна
*самая свежая живая* — спрашиваем сокет и спускаемся по времени
(`session.live_session_for_cwd`).

## Подключение

Проектный `.mcp.json` уже лежит в репозитории — сессия, запущенная в
`~/mop`, подхватит сервер сама. Чтобы он был доступен из любого каталога
(мастер работает в `~/rugent`, `~/cloudpub`):

```
claude mcp add --scope user mop /home/ermak/mop/bin/mop-mcp
```

Проверка без claude — сервер печатает число инструментов и найденный инбокс
мастера:

```
mop-mcp --check
```
