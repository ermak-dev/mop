# MOP. Master of Puppets

  <img src="docs/cover.jpg" width="100%" alt="обложка">
</p>

Рой агентов (папетов).  Мастер раздаёт задачи, папеты на узлах пула их делают.

## Термины

- Мастер (master): сессия на управляющей машине, которая держит очередь задач трекера, раздаёт их папетам и принимает отчёты. Поднимается командой `mop master` в рабочей копии проекта.
- Папет (puppet): агент, который делает задачу. Живёт в tmux на узле пула, работает в своей рабочей копии, о результате отчитывается мастеру по шине.
- Узел (node): машина пула, на которой живут папеты. Либо машина с Linux, где папеты работают процессами в общей среде, либо гипервизор Proxmox, где каждый папет изолирован в контейнере LXC.
- Рабочая копия (workspace): собственный клон репозитория у папета на узле. Окружение под проект в нём настраивает `.mop/workspace.yaml`.
- Шард (shard): проект в пуле. Папеты одного репозитория образуют срез пула, и мастер проекта видит только их.

## Установка

1\. Клонировать репозиторий и вывести команду наружу. Всё запускается через `mop <подкоманда>`.

```
git clone <адрес> ~/mop
sudo ln -s ~/mop/bin/mop /usr/local/bin/mop
```

2\. Настроить установку. Три файла, каждый копируется из примера и заполняется, в git они не попадают.

2.1. `.env`, настройки установки.

```
cp .env.example .env && chmod 600 .env
```

- `MOP_SERVER_LAN`, обязательная: адрес сервера в локальной сети. На него ходят и узлы, и мастер.
- `MOP_GIT_HOST`, обязательная: хост, с которого папеты клонируют проекты.
- `Z_AI_KEY`, опционально: если используется модель `GLM` от z.ai

Весь словарь с текущими значениями показывает `mop config`.

2.2. `inventory.yaml`, машины и их роли, формат `Ansible`. Одна машина может быть в нескольких ролях.

```
cp inventory.yaml.example inventory.yaml
```

- `server`: Nomad-сервер и шина NATS. Машина оркестратора.
- `puppet`: узлы пула, на них живут папеты.
- `master`: управляющая машина, откуда запускают `mop`.
- `proxmox`: узлы Proxmox, где папет живёт в контейнере LXC. Такой узел перечисляют и в `puppet`.

2.3. `setup.yaml`, окружение папетов, общее для всех проектов установки. Это список задач ansible, он проигрывается на узлах и при сборке образа шарда.

```
cp setup.yaml.example setup.yaml
```

- Тулчейн, ваши скиллы, ваши MCP-серверы.
- В примере лежит окружение чужой установки: выкиньте лишнее и впишите своё.
- Нужное одному проекту сюда не пишут, для этого есть `.mop/` в самом проекте.

3\. Развернуть пул. Один прогон ставит кластер Nomad, окружение узлов, шину с агентом и сторожем диска. Прогон идемпотентен, упавшее чинят повторным запуском.

```
mop deploy
```

4\. Раздать логин. `claude login` на управляющей машине, затем `mop login` разносит логин claude.ai и ключи LLM по узлам пула.

5\. Проверить: `mop list` показывает пул и живых агентов, `mop doctor` даёт диагностику целиком.

## Подключение проекта

Проект должен быть доступен по git с `MOP_GIT_HOST`: узлы клонируют его сами.

1\. При необходимости положить в корень проекта каталог `.mop/` с двумя плейбуками ansible. Оба необязательны, многим проектам хватает общего окружения из `setup.yaml`. 

1.1. `.mop/node.yaml` исполняется для сборки образа контейнера или настройки узла. В `vars` можно запросить ресурсы для папета

```yaml
---
- name: Resources required for puppet
  vars:
    MOP_MEM_MB: "8192"
    MOP_DISK_GB: "50"
    MOP_CORES: "4"
```

1.2. `.mop/workspace.yaml` исполняется внутри контейнера перед запуском папета. В нем можно, например, скоприровать частно меняющиеся файлы, ключи API и тд.


2\. Завести шард в пуле. Прогон заводит шарду пользователя на шине, раздаёт креды мастеру и папетам и проигрывает задачи проекта на узлах. Какие шарды уже заведены, показывает `mop shards`.

```
cd ~/project
mop deploy
```

3\. Только для гипервизоров: собрать образ шарда. Сборка впекает размеры и окружение из `.mop` в образ, дальше каждый папет клонируется из него. После правки `.mop` образ собирают заново. Без аргумента в рабочей копии проекта сборка берёт `.mop` из её файлов как лежат, без коммита и push, так правку манифеста проверяют до влития в master.

```
mop driver build
```

4\. Начать работу. `mop master` в рабочей копии проекта поднимает мастера с кредами шарда, `mop add` заводит папета. Результат виден в `mop list`.

## Использование

Запустите `mop master` в рабочей копии проекта. Поднимется claude code, который видит только папетов этого проекта: ростер, состояние, переписку.

В этой сессии скилл `/master` ведёт разбор и раздачу задач. Например:

```
> /master Дай мне на разбор первую задачу из трекера.
...
Я разобрал задачу, вот её суть и предложенный фикс. Одобряешь или правим?
...
> Одобряю
...
Задача одобрена, отдаю её в пул. Жду отчёта от папетов.
...
Задача выполнена, реализация проверена. Выдаю landing-токен.
...
Задача успешно приземлена в интеграционную ветку.
> Следующая задача
```

Скилл живёт в `skills/master`. Он держит очередь заявок трекера и разбирает их с вами по одной: суть, свидетельства, предлагаемый фикс. Ничего не уходит в работу без одобрения. Одобренное он раздаёт свободным папетам, каждый делает фикс в своём клоне и присылает отчёт. В интеграционную ветку изменения садятся по одному, через landing-токен, а полный гейт гоняется уже на интегрированном результате. Размер пула скилл держит сам: заводит папетов под одобренную работу, отпускает их, когда очередь кончилась, лечит залипших.

### Командная строка

Полный список подкоманд даёт `mop` без аргументов. Чаще прочего нужны:

```
mop list                   ростер в терминале (в сессии мастера то же даёт инструмент agents)
mop shards                 какие шарды заведены в пуле
mop attach <имя>           живой терминал папета (ssh + tmux)
mop deploy <git-origin>    завести новый шард
mop driver build [origin]  собрать образ шарда на гипервизорах; без аргумента берётся эта рабочая копия
mop node                   узлы пула: драйвер, шарды, ёмкость
mop recycle <имя>          пересоздать папета на чистой рабочей копии
mop disk / mop gc          место на узлах, подробности в docs/GC.md
```

### Модели

`mop llm` перечисляет профили, которыми поднимают папетов, и показывает, чей ключ есть в `.env`. Профиль выбирают при создании папета (`mop add --llm профиль`) и для сессии мастера (`mop master --llm профиль`). `mop code --llm профиль` поднимает на том же профиле обычную сессию claude без шарда и без пула, когда нужна только модель.

Сейчас есть профили `claude` (подписка claude.ai) и `glm` (`Z_AI_KEY` в `.env`). Новый профиль добавляется файлом в `mop/llm/` по образцу.

### Место на узлах

`mop disk` показывает свободное место. `mop gc` пересоздаёт свободных папетов на узлах, где места не хватает, занятых не трогает. Мусор в рабочих копиях подрезает сторож на самом узле, подробности в [docs/GC.md](docs/GC.md).

## Если что-то сломалось

Диагностика: `mop doctor` в терминале или инструмент `doctor` в сессии мастера. `--fix` чинит то, что чинится само. Другой дороги на узел, кроме шины, нет: упавший агент и битые креды лечат повторным `mop deploy`.
