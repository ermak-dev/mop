# mop - Master Of Puppets

Пул claude-слейвов: управляющая машина (мастер) раздаёт задачи, а сессии
claude code на остальных машинах (слейвы, на узлах пула) их делают. Где
встаёт слейв, решает Nomad, сообщения между мастером и слейвами возит NATS.

Слейв живёт в tmux на узле и работает с собственной рабочей копией проекта.
Проект здесь называют шардом: слейвы одного репозитория образуют срез пула,
и мастер этого проекта видит только его, чужие для него не существуют.

## Что нужно

* Машины: одна всегда включённая под сервер (Nomad и шина) и сколько угодно
  узлов под слейвов. Узлом годится линукс семейства Debian, остальное плейбук
  ставит сам; слейв бронирует 8 ГБ памяти.
* Все машины под одним пользователем, узлы доступны управляющей машине по ssh.
* На управляющей машине: python3, ansible, git.
* claude code на узлах: с логином claude.ai или ключом LLM-провайдера.
* Инвентарь ansible `~/etc/inventory.ini`, общий с остальными плейбуками,
  с группами `mop_server` (сервер), `nomad_clients` (узлы пула) и
  `nomad_control` (управляющая машина).

## Установка

1. Клонировать репозиторий и вывести команду наружу:

       git clone <адрес> ~/mop
       sudo ln -s ~/mop/bin/mop /usr/local/bin/mop

   Всё запускается через `mop <подкоманда>`: диспетчер настраивает окружение,
   файлы из `bin/` напрямую не вызываются.

2. Завести настройки:

       cp .env.example .env && chmod 600 .env

   Обязательная настройка одна: `MOP_SERVER_LAN`, адрес сервера в локальной
   сети. Из остального вписывают ключ LLM-провайдера (например, `Z_AI_KEY`),
   если слейвы работают не через claude.ai. Что действует сейчас и откуда
   взялось каждое значение, показывает `mop config`.

3. Развернуть пул:

       mop deploy nomad    кластер Nomad: сервер и клиенты
       mop deploy pool     шина, агент и сторож диска на узлах, креды

   `mop deploy pool` запускают и повторно: так заводят на шине новый шард
   и доставляют его креды, `mop deploy pool <git-origin>`. Цели `homelab`
   и `claude` к продукту не относятся, это установка автора из `examples/`.

4. Залогинить claude: `claude login` на управляющей машине, затем `mop login`
   раздаст логин claude.ai и ключи LLM на узлы пула.

Дальше помогает `mop list` (кто где и живы ли агенты) и `mop doctor`
(диагностика целиком).

## Использование

Полный список подкоманд даёт `mop` без аргументов. Основное:

### Слейвы

Команды адресуются по имени, `sl-<проект>-<номер>`; имена видны в `mop list`.

```
mop add [git-origin]       создать слейва: origin по умолчанию текущей копии
mop list                   кто где, занят или свободен, чем поднят
mop tail <имя>             хвост tmux-буфера слейва
mop attach <имя>           подключиться к tmux-сессии слейва (по ssh)
mop send <имя> <текст>     послать сообщение слейву
mop restart <имя>          перезапустить зависшего
mop recycle <имя>          пересоздать на чистой рабочей копии
mop change <имя> <origin>  перенацелить слейва на другой проект
mop wipe <имя>             снести рабочую копию (остановленному)
mop delete <имя>           удалить слейва
```

### Мастер

В рабочей копии проекта `mop master` поднимает claude, который видит слейвов
своего шарда: ростер, состояние, отправка задач, приём отчётов. Какой срез
пула уже заведён, показывает `mop shards`. Петля управления (триаж задач,
диспатч слейвам, посадка конфликтующих изменений по одному) описана скиллом
`pm` из `skills/pm`.

### Модели

`mop llm` перечисляет профили, которыми поднимают слейвов, и показывает, чей
ключ есть в `.env`. Профиль выбирают при создании слейва (`mop add --llm
ПРОФИЛЬ`) и для сессии мастера (`mop master --llm ПРОФИЛЬ`).

### Место на узлах

`mop disk` показывает свободное место. `mop gc` пересоздаёт свободных слейвов
на узлах, где его не хватает; занятых не трогает. Мусор в рабочих копиях
подрезает сторож на узле сам, подробности в [docs/GC.md](docs/GC.md).

## Если что-то сломалось

`mop doctor` ловит залипания, протухший логин и исчерпанную квоту модели,
`mop doctor --fix` чинит то, что чинится само. Дороги на узел мимо шины нет:
упавший агент и битые креды лечатся повторным `mop deploy pool`.
