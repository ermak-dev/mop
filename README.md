# mop

Пул claude-слейвов поверх Nomad: как он разворачивается, чем управляется и как
с слейвами разговаривать.

```
mop/               библиотека: всё знание о пуле, возвращает данные и не печатает
  nomad.py           связь с Nomad: джобы, аллокации, ёмкость узлов
  bus.py             шина: синхронный клиент NATS, адресует узлы
  agent.py           то, что отвечает на узле: закрытый набор глаголов
  slaves.py          спека job'а, LLM-профили, состояние слейва, диагностика
  session.py         файлы сессий claude и протокол канала (standalone)
  keys.py            раздача кредов и ключей провайдеров на узлы
  render.py          таблицы
bin/mop            диспетчер: mop <подкоманда>; наружу торчит ~/bin/mop
bin/common         общее окружение командлетов (молчит: mcp говорит по stdio)
bin/lib.py         общая часть питоновских командлетов — единственное, что печатает
bin/add …          по командлету на подкоманду: add/list/delete/change/restart/
                   attach/tail/llm/login/doctor/send/master/shards/mcp/deploy/help
nomad/             ansible: сам Nomad, узлы, уборка диска
nats/              ansible: шина и агент на узлах
tests/state.py     матрица состояний слейва, проверяется без пула
skills/pm/         скилл мастера: петля управления пулом (симлинк из ~/.claude)
docs/BUS.md        субъекты шины, глаголы агента, права
docs/CHANNEL.md    протокол канала сообщений claude code
docs/MCP.md        архитектура MCP-сервера и его инструменты
```

Печатают только фронтенды в `bin/`. Библиотека возвращает данные — иначе
MCP-сервер начал бы разбирать текст, свёрстанный для терминала.

## Как это связано

Два слоя, и это не формальность.

**Nomad решает, где слейв стоит.** Размещение, бюджет памяти, рестарты,
переезд при потере узла. `slave` ходит в него по REST
(`https://nomad.ermak.dev`), токен — из `$NOMAD_TOKEN` или
`~/.config/nomad/bootstrap.json`, и живёт этот токен ТОЛЬКО на управляющей
машине.

**Шард решает, чей он.** Проект — это шард: `mop master` в рабочей копии
поднимает claude, который видит и достаёт только слейвов своего репозитория.
Мастеров можно держать сколько угодно, в том числе несколько на один проект.
Границу держат креды NATS и проверка агента, а не уговор.

**Шина решает, как с ним разговаривать.** Сообщения, состояние, ввод в TUI,
раздача кредов — всё через NATS до агента на узле ([docs/BUS.md](docs/BUS.md)). Прежний
`alloc exec` удалён: он резал сообщения по 8 КБ и стоил websocket-рукопожатия
за каждую пробу. Аварийный путь теперь — ansible, `nats/setup.yml`.

ssh остаётся только для `mop attach`, ради живого терминала.

Каждый слейв — это job Nomad, чей врапер доводит узел до состояния «клон есть,
claude живёт в tmux» и держится, пока жива tmux-сессия. Смерть врапера =
рестарт или переезд слейва силами Nomad. Агент узла живёт отдельно от джобов,
под systemd: он должен отвечать и тогда, когда слейв перезапускается.

## Симлинки наружу

Проект живёт отдельным репозиторием, но снаружи на него ссылаются —
это интерфейсы: три пути наружу.

```
~/bin/mop              -> ../mop/bin/mop
~/etc/nomad            -> ../mop/nomad
~/etc/nats             -> ../mop/nats
~/.claude/skills/pm    -> /home/ermak/mop/skills/pm
```

`~/.claude/skills/pm` абсолютен намеренно: тот же путь обязан разрешаться и на
узлах пула, куда `claude.yml` раскатывает скиллы — правда, уже разыменованными.

`~/etc/nomad` и `~/etc/nats` обязательны: `net setup <имя>` разворачивается в
`~/etc/<имя>/setup.yml` по одному только соглашению о пути, и `~/etc/site.yml`
импортирует плейбуки относительно `~/etc`. Таблицы «имя → плейбук» нигде нет,
путь и есть таблица. По этой же причине шина живёт отдельным каталогом
`nats/`, а не внутри `nomad/`.

## Внешние зависимости

* `~/etc/inventory.ini` — инвентарь ansible, общий с остальными плейбуками
  (живёт в репозитории backup, сюда не переезжает).
* `.env` — секреты проекта, в репозиторий не коммитятся. Всё, что задаёт
  человек: креды GitLab, ключи LLM-провайдеров, токены MCP-серверов. На узлы
  уезжает **только названное явно** — ключи, которые просит профиль из
  `LLM_PROFILES`, и `NODE_SECRETS`; креды GitLab пул не видит.
  Порождаемого само тут нет: пароли NATS заводит плейбук в
  `~/.config/mop/secrets/`, токен Nomad приезжает из его бутстрапа, логин
  claude.ai кладёт `claude login`.
* `~/.claude/.credentials.json` — логин claude.ai, который `mop login`
  раздаёт на узлы пула.

## Запуск плейбуков

```
net setup nomad                                  # или:
ansible-playbook -i ~/etc/inventory.ini ~/etc/nomad/setup.yml
ansible-playbook -i ~/etc/inventory.ini ~/etc/nomad/claude.yml
net setup nats                                   # шина и агенты
```

`nats/setup.yml` — аварийный путь пула: дороги на узел мимо шины нет, и упавшего
агента поднимают только им.
