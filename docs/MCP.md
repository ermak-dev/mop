# mop mcp

MCP-сервер пула: ростер, канал сообщений папетам и управление их джобами.
Встроенные SendMessage/ListAgents для этого не годятся — они адресуют сессии
только этого хоста, а папеты живут на узлах пула.

Реализация — `bin/mcp`, запуск — `mop mcp`, транспорт stdio. Протокол канала —
[CHANNEL.md](CHANNEL.md), субъекты шины — [BUS.md](BUS.md).

## Топология

```
сессия мастера (управляющая машина)
   └─ stdio ─> mop mcp ──REST──> Nomad        джобы, размещение, память
                  │
                  ├──── NATS ──> mop-agent    узел: папет pu-*
                  │                   ↓        cc-socks/<pid>.sock
                  │             сессия папета
                  │                   │ mop mcp папета: send(to=<адрес мастера>)
                  └── инбокс мастера <┘ mop.<шард>.master.<id>.inbox
```

Сокет сессии — unix-сокет, host-local, поэтому до него дотягивается агент,
который живёт на том же узле.

## Три профиля

Профиль решают факты окружения, а не флаг:

| Профиль | Когда | Инструменты |
|---|---|---|
| мастер шарда | токен Nomad + `MOP_SHARD` (ставит `mop master`) | канал и управление, только свой срез пула |
| оператор | токен Nomad без шарда | то же по всему пулу |
| узел | токена нет (сессия папета на узле) | один канал; ростер — опросом самой шины (глагол `local`) |

Так узел физически не может позвать то, чего ему не положено, вместо того
чтобы не звать по уговору. Транспорт stdio, а не HTTP: на управляющей машине
у сервера под рукой management-токен Nomad, и слушать порт с ним — лишний риск.

## Инструменты

| Инструмент | Профиль | Аннотация | Аргументы |
|---|---|---|---|
| `agents` | все | readOnly | `project` |
| `send` | все | — | `to`, `message`, `priority`, `notify_when_idle`, `wait_seconds` |
| `tail` | все | readOnly | `name`, `lines`, `grep` |
| `pool` | мастер, оператор | readOnly | — |
| `puppet` | мастер, оператор | destructive | `action: add\|remove\|restart\|update`, `name`, `origin`, `llm`, `fresh` |
| `doctor` | мастер, оператор | destructive | `fix` |
| `slash` | мастер, оператор | destructive | `name`, `command` |
| `login` | мастер, оператор | destructive | — |

Аннотации не косметика: по ним Claude Code решает, спрашивать ли разрешение.

* `send` принимает ТРИ адреса: папет пула (`pu-<проект>-<n>`, узнаётся по
  префиксу), сессия этого хоста и мастер шарда — по его инбоксу на шине. Адрес
  мастера папету не выдумывать: он приезжает в конверте каждого сообщения
  (`from-name`) и показывается в `agents`. Возвращается **вердикт доставки**, а
  не факт отправки.
* Push без опроса: `notify_when_idle` ждёт не сервер, а агент узла рядом с
  сокетом папета; дождавшись простоя, он публикует весть в инбокс мастера, и
  сервер кладёт её в сессию (`CLAUDE_CODE_MESSAGING_SOCKET`).
* Тела инструментов завёрнуты в `loud`: исключение MCP приезжает модели как
  «Error executing tool <имя>» без причины, и отказ обязан называть себя.
* `slash` работает по белому списку (`/model`, `/clear`, `/compact`, `/rc`,
  `/status` и Escape); без списка это произвольный ввод в чужую сессию.
* `puppet(update)` со сменой одного профиля поднимает папета НА ТОЙ ЖЕ
  истории каталога: тикет переезжает на другую модель посреди дела. Разрешение
  на это — разовый токен в спеке, который врапер гасит маркером в клоне, а не
  постоянный флаг. Иначе его подхватил бы и `restart`, то есть ЛЕЧЕНИЕ, и
  залипший папет возвращался бы ровно в тот контекст, на котором залип.
  `fresh=true` и смена репозитория поднимают чисто.
* `attach` намеренно вне MCP: живой терминал инструментом не отдать.

## Подключение

Проектный `.mcp.json` уже лежит в репозитории — сессия, запущенная в `~/mop`,
подхватит сервер сама. На узлах пула его регистрирует `mop deploy`
(deploy/setup.yml), и врапер папета доподстраховывается той же командой на
каждой загрузке. Чтобы сервер был доступен из любого каталога на мастере:

```
claude mcp add --scope user mop $HOME/mop/bin/mop mcp
```

Проверка без claude — сервер печатает профиль, число инструментов и инбокс:

```
mop mcp --check
```

## Зависимости

`mcp` (питоновский SDK, 2.x — в нём FastMCP переименован в `MCPServer`) и
`nats-py`:

```
pip3 install --user --break-system-packages mcp nats-py
```
