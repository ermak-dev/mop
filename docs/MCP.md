# mop mcp

MCP-сервер пула: ростер, канал сообщений папетам и управление их джобами.
Встроенные SendMessage/ListAgents для этого не годятся — они адресуют сессии
только этого хоста, а папеты живут на узлах пула.

Реализация — `mop/cli/service/mcp.py`, запуск — `mop mcp`, транспорт stdio. Протокол канала —
[CHANNEL.md](CHANNEL.md), субъекты шины — [BUS.md](BUS.md).

## Топология

```
сессия мастера (машина оператора)
   └─ stdio ─> mop mcp ─NATS─> mop-cluster    джобы, размещение, память
                  │            (сервер: Nomad за шиной, docs/CLUSTER.md)
                  │
                  ├──── NATS ──> mop-agent    узел: папет pu-*
                  │                   ↓        cc-socks/<pid>.sock
                  │             сессия папета
                  │                   │ mop mcp папета: send(to=<адрес мастера>)
                  └── инбокс мастера <┘ mop.<проект>.master.<id>.inbox
```

Сокет сессии — unix-сокет, host-local, поэтому до него дотягивается агент,
который живёт на том же узле.

## Три профиля

Профиль решают факты окружения, а не флаг:

| Профиль | Когда | Инструменты |
|---|---|---|
| мастер проекта | кред оператора (`mop join`) + `MOP_PROJECT` (ставит `mop master`) | канал и управление, только свой срез пула |
| оператор | кред оператора с ролью `admin` без проекта | то же по всему пулу |
| узел | кред `puppet-<проект>` (сессия папета на узле) | один канал; ростер — опросом самой шины (глагол `local`) |

Профиль выводится из того, ПОД КЕМ процесс на шине: пользователь NATS и есть
набор прав, а `puppet-<проект>` в субъект сервиса кластера не пишет вовсе. Так
узел физически не может позвать то, чего ему не положено, вместо того чтобы не
звать по уговору.

Раньше здесь стояла проверка «есть ли токен Nomad»: она отвечала верно ровно
потому, что токен возили только мастерам. Управление уехало за шину (#80, #81),
и вопрос вернулся к своей настоящей формулировке — чьи у нас креды.

Транспорт stdio, а не HTTP: слушать порт у процесса, которому положены все
проекты установки, — лишний риск.

## Инструменты

Два вида, и граница между ними не вкусовая.

**Ручные** — у них состояние процесса сервера, командлетом их не выразить:

| Инструмент | Профиль | Аннотация | Аргументы |
|---|---|---|---|
| `agents` | все | readOnly | `project` |
| `send` | все | — | `to`, `message`, `priority`, `notify_when_idle`, `wait_seconds` |
| `tail` | все | readOnly | `name`, `lines`, `grep` |
| `slash` | мастер, оператор | destructive | `name`, `command` |

**Командлеты** (#160) — всё управление пулом. Командлет, объявивший в своём
модуле `MCP = {...}`, становится инструментом мастера и оператора; своей
реализации операций в сервере нет. Первая копия разошлась с командлетами за
полсотни изменений: `puppet(add)` не слал workspace (#133), `build` собирал
образ мимо сборщика сервера (#123).

```python
# mop/cli/core/update.py
MCP = {"annotations": "destructive", "args": [
    {"name": "name", "type": "string", "required": True, "help": "..."},
    {"name": "origin", "type": "string", "help": "..."},
    {"name": "llm", "type": "string", "flag": "--llm", "help": "..."},
    {"name": "fresh", "type": "boolean", "flag": "--fresh", "help": "..."}]}
```

* Имя инструмента — слова команды через подчёркивание (`node_drain`,
  `project_add`), описание — докстринг командлета целиком.
* Аргумент без `flag` — позиционный, по порядку; необязательные — только в
  хвосте. `boolean` и `integer` — только флагом. Позиционное значение с
  дефисом впереди — отказ: иначе одно поле включало бы чужой флаг.
* Вызов — `mop <команда> <argv>` подпроцессом из **каталога сессии**
  мастера, а не процесса сервера: origin и workspace командлет берёт из
  рабочей копии, в которой стоит мастер. Ответ — вывод как есть, без цветов;
  отказ — `FAILED (exit N)` и вывод. Успех без вывода — `done`: быстрые
  команды молчат, результат виден в `agents`.
* `"background": True` — ответ сразу, итог приходит вестью в сессию тем же
  путём, что вести агентов. Так идёт `project_add`: сборка образа — минуты.
* Объявление читается разбором AST, без импорта модуля, и кривое роняет
  старт `mop mcp` с именем файла, а не прячет инструмент молча;
  `tests/cli.py` разбирает все объявления дерева.
* Командлет без объявления в MCP не виден: `attach` (живой терминал
  инструментом не отдать), `master`, `code`, службы.

Сейчас объявлены: `add`, `delete`, `restart`, `update`, `recycle`, `wipe`,
`stat`, `doctor`, `login`, `node`, `node drain`, `node up`, `project add`,
`project limit`. Список — `mop mcp --check` в числе инструментов, а
поимённо — у клиента.

Аннотации не косметика: по ним Claude Code решает, спрашивать ли разрешение.

* `send` принимает три адреса: папет пула (`pu-<проект>-<n>`, узнаётся по
  префиксу), сессия этого хоста и мастер проекта — по его инбоксу на шине. Адрес
  мастера папету не выдумывать: он приезжает в конверте каждого сообщения
  (`from-name`) и показывается в `agents`. Возвращается **вердикт доставки**, а
  не факт отправки.
* Push без опроса: `notify_when_idle` ждёт не сервер, а агент узла рядом с
  сокетом папета; дождавшись простоя, он публикует весть в инбокс мастера, и
  сервер кладёт её в сессию (`CLAUDE_CODE_MESSAGING_SOCKET`).
* Тела инструментов завёрнуты в `loud`: исключение MCP приезжает модели как
  «Error executing tool <имя>» без причины, и отказ обязан называть себя.
* `slash` работает по белому списку (`/model`, `/clear`, `/compact`, `/rc`,
  `/status` и Escape); без списка это произвольный ввод в чужую сессию.

## Подключение

Проектный `.mcp.json` уже лежит в репозитории — сессия, запущенная в `~/mop`,
подхватит сервер сама. На узлах пула его регистрирует `mop server deploy`
(deploy/setup.yml), и врапер папета доподстраховывается той же командой на
каждой загрузке. Чтобы сервер был доступен из любого каталога на мастере:

```
claude mcp add --scope user mop $HOME/mop/bin/mop mcp
```

Проверка без claude — сервер печатает профиль, число инструментов и инбокс:

```
mop mcp --check
```

## Зависимости

`mcp` (питоновский SDK, 2.x — в нём FastMCP переименован в `MCPServer`) и
`nats-py`:

```
pip3 install --user --break-system-packages mcp nats-py
```
