# Чат и терминал живой сессии

Эпик #594 расширяет экран папета двумя независимыми представлениями:
структурированной историей разговора и настоящим терминалом того же процесса.
Это не отдельный агент, не второй `claude --resume` и не перевод рабочего
папета в daemon. Локальные особенности Claude описаны в [CLAUDECODE](CLAUDECODE.md),
права и доставка — в [BUS](BUS.md), HTTP — в [WEB](WEB.md).

## Работа с интерфейсом

В окне папета только две вкладки: первым открывается чат, вторая — настоящий
терминал. До появления tmux терминал показывает приватный ход инициализации
(#612) и сам переходит к живому PTY после подтверждения сессии; преждевременный
ввод отключён. Кнопка «Последние строки» в терминале открывает ограниченный,
редактированный сервером снимок старого scrollback (до 1000 строк), в том
числе строки до подключения PTY. Это просмотр, не второй терминал и не
подмена текущих байтов xterm. У снимка сохранены масштаб, обновление,
признак обрезания и безопасный статус ошибок. В ленте чата отсутствие live
history не подменяется пустым ответом.

Терминал сначала открывается для чтения. «Взять управление» — явный переход
в режим writer, который может быть только один на папета. Это управление
вводом не отменяет аренду работы: чужая живая аренда, чужая или ничейная работа
и неизвестные факты не дают взять управление. В свою dirty/ahead работу
продолжать писать можно (#595). Другие административные действия не получили
это исключение.

Человеческий composer использует только явно полученный writer. Multiline
и Unicode отправляются bracketed paste + Enter; slash-команда проходит через
тот же настоящий CLI input, не через peer messaging. Команда «отправлена»
не означает «исполнена»: меню может требовать дополнительного ввода в терминале.
Текущая незавершённая строка не стирается автоматически. Отдельная сворачиваемая
форма «Сообщение папету через канал» в чате сохраняет прежний peer-send через
admin operations: для него не требуется terminal writer, но он доступен только
после подтверждённого screen-источника. Его вердикт доставки не выдаётся за
исполнение команды CLI, а черновик переживает переход между вкладками.

«Остановить ход» отправляет Escape в текущий CLI. Это не остановка Nomad job,
не убийство процесса и не гарантия отмены всех фоновых задач. Остановка самого
задания — отдельное административное действие #608. Комбинированное
«прервать и отправить» доступно только при доказанном `interrupt_delay_ms`
из текущего tmux escape-time: Escape и paste — разные input sequences с
этой паузой. Отсутствующая timing metadata не заменяется догадкой;
обычные Stop и Send остаются отдельными действиями. Пауза не подтверждает
завершение инструмента. Terminal menus,
permissions и разрешённые профилем вопросы остаются штатным интерфейсом;
фиктивных веб-форм согласования нет.

При неопределённом ответе на ввод интерфейс не повторяет bytes и прекращает
дальнейший ввод через старое подключение. Переподключение writer и новое
управление требуют явного действия. После `/clear`, `/resume` или замены
процесса старый writer не должен продолжать ввод в новый разговор.

## Приватный путь данных

```text
браузер → private HTTP → server bridge → private node RPC → tmux attach PTY
                      → history RPC → session.py → текущий JSONL
```

Веб-процесс работает своей service identity, но проверяет действующего
admin-пользователя на каждом запросе. Token терминала закреплён за целью,
логином и принятой cookie-сессией браузера. Другая cookie того же логина не
может управлять этим token. В `POST` обязателен проверенный Origin и JSON.
Роль или исходящие capabilities целевого папета не дают viewer полномочий.

Ни history records, ни keyboard bytes, ни tid не идут в public `/events`,
публичный снимок или operation verdict. Take/release управления имеют общую
безопасную audit-запись без содержимого разговора. Ответы — `no-store`.
Авторизация повторяется после long-poll до выдачи bytes.

Полный терминал — доверенная административная capability исполнения кода в
теле, включая Claude `!` и tmux commands. Ограниченный список клавиш не является
границей безопасности. Raw terminal не редактирует секреты в потоке; его
нельзя публиковать гостю. Redaction прежнего tail не отменяется.

## История

Private history возвращает `epoch`, `session_id`, `cursor`, `records`,
`reset`, `has_more`, `partial`. Cursor не является полномочием и не содержит
разрешённый клиентом путь; его проверяет reader внутри тела. При reset старая
живая лента заменяется, а не приписывается к новому разговору.

Reader сохраняет валидные JSON-объекты, включая неизвестные record types.
Инструменты связываются по tool IDs, error/result сохраняются; prose не
используется как доказательство исполнения. История не считается токеновым
stream: записи могут появляться позже терминального вывода.

Чтение ограничено порциями; неполная обычная строка остаётся pending.
Завершённые битые записи и oversized records представлены честными
content-free notices с byte offset и числом пропущенных bytes, не мнимым
ответом ассистента. До первого файла доказанная живая сессия даёт пустой
pending, а неизвестная identity — отказ.

Linux identity связывает registry, PID/start ticks, inbox socket peer,
реальные cwd/config home и sessionId. Terminal также связывает foreground
pane/TTY. Пробы и последующая PTY write не один атомарный syscall; такой
гарантии интерфейс не обещает. In-place переписывание, не изменившее ни bytes,
ни inode/size/observable timestamps, невозможно отличить от неизменного файла.

Текущий reader не объединяет отдельные файлы subagents и отказывает при
symlink в защищённом пути или project slug длиннее 200 символов. Эти отказы
не маскируются пустой историей. Веб не принимает произвольный transcript path.

## Терминальный транспорт и лимиты

Node запускает существующий `driver.attach_argv` под настоящим controlling
PTY. Read-only tmux client имеет `read-only,ignore-size`; он не вводит и не
меняет размер рабочего окна. Writer resize влияет на настоящий CLI и другие
представления этой tmux-сессии. Высота xterm совпадает с высотой, которую
измеряет FitAddon: padding родителя не крадёт нижнюю строку (#621).
Вертикальная прокрутка появляется только при настоящем scrollback, который
остаётся доступным; старые строки до attach берутся отдельным снимком.

Node имеет пять private named verbs: `term_open`, `term_read`, `term_write`,
`term_resize`, `term_close`. Они доступны только admin namespace; человеческий
actor передаётся доверенным фронтендом, а не выбирается в браузерном JSON.
Input sequence начинается с 1 и идёт подряд; повтор последней подтверждённой
sequence не набирает текст снова. Потерянные старые receipts — unknown, не
разрешение повторить операцию.

Ring ограничен 512 KiB, output page — 64 KiB, input — 4 KiB, read wait —
15 секунд. Server удерживает не более восьми attachments и не допускает
двух одновременных long-polls одного handle. Writer idle — 30 секунд,
reader — 60 секунд; успешная активность продлевает срок. Переполнение cursor
даёт reset и требует нового attach/redraw, не regex-удаления ANSI.

`term_close` закрывает attach client, не саму tmux-сессию. Definite failed
writer open откатывает собственную staged identity/lease; новый чужой claim
не стирается. Ошибка rollback сохраняет реальное состояние и причину.

## CLI и MCP

Командлеты используют те же узловые операции; MCP получает их декларации,
не вторую реализацию управления:

```text
mop session history <name> [--cursor cursor]
mop session terminal <name> open --mode ro
mop session terminal <name> open --mode rw --cols 100 --rows 30
mop session terminal <name> read <tid> --cursor 0 --wait 15
mop session terminal <name> interrupt <tid> --seq 1
mop session terminal <name> input <tid> --seq 2 --data <base64>
mop session terminal <name> close <tid>
```

Raw terminal RPC требует человеческую operator identity на шине. История
master-scoped в проекте цели. Ответ — ограниченный JSON, без превращения
терминальных bytes в управляющий вывод самого командлета. Unknown input
имеет отдельный результат и не повторяется автоматически.

## Проверки и границы приёмки

`mop dev chat-probe` (#613) проверяет реальный Claude/tmux с loopback fixture
провайдером. Он отдельно отмечает observed, unknown и unsupported. Проверено
на 2.1.296: Unicode/multiline, local slash, model change, registry/key identity,
clear, Escape stream/Bash interruption, permission prompt и actual history.
В bare tool set AskUserQuestion отсутствовал; это не успешная проверка вопроса.
Все запросы использовали dummy key. Git SSH заблокирован, managed settings
закрывают запуск, собственные PID/start identities проверяются при cleanup.
Это не OS network sandbox и не проверка платного провайдера.

`mop dev chat-smoke` (#615) проверил настоящий Claude 2.1.296 через
private HTTP → server bridge → node Registry → собственный tmux PTY.
Использован loopback fixture provider с фиктивным ключом; bus boundary и
тестовая identity подставлены, чтобы не входить в рабочий пул. Результат
не выдаётся за проверку реального NATS, контейнерного SSH или платного
провайдера. Отчёт с временным browser cookie остаётся приватным на машине
исполнения, не в Git, артефактах и общем журнале.

| Проверка в fixture | Наблюдение |
|---|---|
| Admin/Origin и чтение | Неавторизованный GET и чужой Origin отвергнуты; приватная история и card читаются |
| Read-only attach и writer | Реальные terminal escape bytes доставлены в браузер, RO write отвергнут; второй writer получил 409 |
| Ввод и команды | Unicode/multiline дошли до fixture request; `/help` остался локальной командой CLI без model call |
| Разговор | `/clear` сменил session_id/epoch, старый writer отказал, прежний cursor дал reset |
| Прерывание | Escape прервал stream и Bash, дочерние shell/sleep исчезли, следующий ход завершился |
| Окно CLI | До одобрения Bash не стартовал; `AskUserQuestion` отсутствовал в bare tool set и не засчитан |
| Lifecycle | Resize реально изменил tmux, потерянный ответ не повторил input, logout отозвал handle, после выхода Claude ввод отказал |

Браузерная проверка открыла тот же private fixture с committed hybrid `dist`:
на компьютере видны запись истории, фактический xterm.js-экран и composer;
через явное «Взять управление» отправлен новый fixture prompt, и его ответ
появился в истории. На ширине 375 px вкладки работали без горизонтального
scroll. Эта проверка относится к исходной трёхвкладочной версии #594:
fixture вернул отказ старого panel reader, потому что не моделировал tail;
#612 подтверждён отдельно в установке. Консолидация #622 переносит его
функции в один терминал; её браузерную проверку фиксирует тикет #622.

Итоговый локальный `--keep-serving` teardown обнаружил ожидание abandoned
long-poll в тестовом HTTP server-close. #615 ограничил ожидание; повторный
запуск подтвердил остановку собственных Claude/tmux/fixture threads без
остатков, но завершился намеренно по сигналу до проверки `no-input-after-exit`.
Последняя проверка отдельно прошла в полном запуске без `--keep-serving`.

Ограничения: нет настоящего container SSH/NATS, rollout и платного LLM;
permission prompt показан в default-mode тестовой CLI, тогда как текущие
автономные папеты используют другой профиль. Состояние после `/resume`,
нескольких реальных браузеров и реальные запросы разрешений на пуле остаются
непроверенными. Точные SHA и CI каждого issue и интеграции фиксируются
в #602; CI успех не означает раскатку.

Все issue-ветки интегрируются в `epic/594-chat-terminal`. Зелёный CI эпика
не является rollout. В `master` эпик попадает и раскатывается только по
отдельному явному указанию оператора; задачи не закрываются до раскатки.
