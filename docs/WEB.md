# Дашборд: состояние пула в браузере

`mop server web` отдаёт по HTTP ту же картину, что `mop list`, `mop node` и
`mop stat`, одной страницей на русском, которая обновляется на месте, — и,
с эпика #456, действия над пулом под актуальной admin-ролью. Адрес —
`https://<MOP_SERVER_LAN>/` (порт — `MOP_HTTPS_PORT`, по умолчанию 443):
снаружи дашборд виден только через TLS-прокси nginx на сервере
(`deploy/roles/proxy`, #96). Сам `mop server web` слушает `MOP_WEB_BIND:MOP_WEB_PORT`,
по умолчанию `127.0.0.1:9000`: открытый HTTP рядом с прокси был бы второй
дорогой мимо TLS.

Сертификат — `MOP_TLS_CERT` и `MOP_TLS_KEY` в `.env`, пути на контроллере.
Не заданы — `mop server deploy` один раз заводит самоподписанный в `secrets/` на имя
`MOP_SERVER_LAN`, и браузер о нём предупредит. Продление — заменить файлы и
прогнать deploy: nginx перечитывает сертификат по reload.

Квоты и аккаунты LLM на дашборде не правятся: с #379 они живут в панели
самого прокси ([PROXY](PROXY.md)); admin дашборда получает туда ссылку и
прозрачный шим (`/v8/management/*`, #417).

## Вход и роли (#415)

| Кто | Что видит |
|---|---|
| гость | публичный обзор: ростер, узлы, мастера, нагрузка, расход, публичный журнал |
| вошедший не-admin | то же; приватные части отвечают 403 |
| admin | плюс карточка папета, полный журнал, операции, список проектов |

Вход — `/api/login` по логину/паролю через провайдер сервера; сессия —
кука `Secure; HttpOnly; SameSite=Strict`. Роль перечитывается на каждом
запросе: сменившийся admin → user и упавший провайдер не пускают
(fail closed), а не ходят с ролью на момент входа. `/api/session` отдаёт
странице текущую пару (login, role); `/api/logout` закрывает сессию.

Общая запись чисел и цвета корзин — одна на страницу:
`web/src/components/format.ts`. Запись свободного из всего `N/M` та же, что
`render.ratio` у CLI (#243): случаи сверяют `format.test.ts` и
`tests/render.py`.

Собранный `web/dist` лежит в репозитории: на серверах node нет и не будет
(тулчейн нужен только разработчику и CI), а rumop раскатывается с сервера
вручную, собирать там нечем. Чтобы `dist` не разошёлся с исходниками молча,
его сверяет CI:

| Что | Где |
|---|---|
| собрать `dist` | `mop dev web build` (`npm ci` и `vite build`; нужен node 22) |
| сверить `dist` со свежей сборкой | `mop dev web build --check`: собирает в сторону, различия — списком, код 1 |
| на каждый push | задача `web:dist` в `.gitlab-ci.yml`; `deploy:mop` от неё зависит |
| тесты компонентов | `npm test` (Vitest + Testing Library), `npm run lint`, `npx tsc --noEmit` в `web/` |

Сборка детерминирована: два прогона на одних исходниках дают `dist` байт в
байт. Правка страницы — это правка в `web/src` и пересобранный `dist` в том же
коммите; `web/node_modules` в пакет не едет (список исключений один,
`deploy/group_vars/all.yml`).

## Операции: исполнитель и адаптер

Клик по дашборду — не RPC и не subprocess командлета: POST
`/api/admin/ops` `{action, target?, params}` (#461) проходит гейты
(актуальный admin, Origin, строго JSON, узкая схема — лишние поля режутся
на разборе), ставится задачей приватной очереди и исполняется воркером
`mop/server/opworker.py` (#476) — тонким слоем приёма поверх fsync-журнала,
зовущим библиотечный workflow `mop/common/ops.py` (#458). Результат
читается отдельным GET по id (admin-only, no-store, без payload).
`Operations`/`opworker.register` — одна точка подключения: операция
появляется в HTTP-реестре и в исполнителе одним движением; до регистрации
эндпоинт честно отвечает 404 unsupported.

Перед каждым эффектом воркер спрашивает один инвариант `ops.safety`
(#460): факты клона известны («не знаю» — отказ, AGENT SILENT — папет может
работать), работы в клоне нет, чужой живой аренды нет, disruptive поверх
живой сессии — отказ. `force` у веба нет: чужую работу клик не берёт.
Аудит (`ops.record`): принципал HTTP и сервис-отправитель — отдельные
поля; payload (текст сообщения, bootstrap) в журнале, GET и аудит-записи
не живёт — в приватном файле/задаче с коротким сроком.

Гарантии клика: 202 — только принятие; тот же payload — тот же id
(двойной клик не запускает дважды), другой payload на ту же цель — 409,
пока операция не завершена; конфликтующие действия сериализуются по цели;
`unknown` — не `failed`: эффекта могли и не быть, автоповтора нет, решение
за админом. Рестарт подтверждается наблюдением (#464): прежний running —
не успех; итоги — succeeded/refused/failed/partial/unknown. Перезагрузка
страницы сбрасывает состояние операции в памяти (#465, первый выпуск) —
истинный исход читается по журналу операций и карточке.

## Паритет фронтендов

Одна операция — один слой: CLI, MCP и GUI зовут одно и то же, различаются
только входом и возможностями, разрешёнными себе явно. Таблица — по коду
коммита, не по плану; «в разработке» — тикет эпика, обещаний текст не даёт.

| Действие | CLI | MCP | GUI (admin) | Общий слой |
|---|---|---|---|---|
| send | `mop send` | `send` (ручной) | SendForm (#469), только message | `ops.send_to_puppet` |
| restart | `mop restart --force` | `restart` | RestartBox (#464), с наблюдением, без force | `ops.restart`; воркер #476 |
| add | `mop add` | `add` | AddBox (#472), workspace из origin | `ops.add`; воркер #476 (#470) |
| update | `mop update --fresh --force` | `update` | UpdateBox (#472): keep/replace/remove, без force | `ops.update`; воркер #476 (#470) |
| recycle | `mop recycle` | `recycle` | DestructiveBox (#473/#471), preview и подтверждение | `puppets.recycle`; воркер #476 |
| delete | `mop delete` | `delete` | DestructiveBox (#473/#471), preview и подтверждение | `puppets.delete`; воркер #476 |
| wipe | `mop wipe --force` | `wipe` | DestructiveBox (#473/#471), без force | `puppets.wipe`; воркер #476 |
| смена модели | `mop profile`, `mop models` | `profile`, `models` | ModelBox (#468), каталог фасадом, с телеметрией | `ops.switch_model`; воркер #476 |

Различия фронтендов — выбор каждого, не копия алгоритма:

* CLI работает из рабочей копии мастера: workspace — её локальный снимок
  (`workspace_text`, #334), владение решают ворота аренды, `--force` есть.
* MCP — те же командлеты инструментами (`MCP = {...}`, #160) плюс ручные
  `agents`/`send`/`tail`/`slash`; своей реализации операций в сервере нет.
* GUI — роль admin, workspace add/update выкачивается из origin (#470),
  `force`, `notify` и `wait` не даются вовсе; destructive-действия —
  с preview последствий и точным подтверждением (#473).

## Границы первого выпуска (осознанные)

* send из веба — только адресная доставка (`params: message`): без
  `notify_when_idle`, без ожидания окончания, без двустороннего чата.
* force в вебе нет ни у одной операции: чужая аренда и работа в клоне —
  отказ с именем владельца (#460).
* Состояние операции живёт в памяти страницы (#465): перезагрузка начинает
  заново; доводит журнал операций и карточка.
* `tsc --noEmit`, `npm test` и lint — локальные проверки разработчика;
  CI-гейт по фронтенду — только сборка `web:dist --check`.

## Пять расписаний

Пять опросов стоят по-разному, и один общий круг показывал бы состояние с
опозданием на самый медленный:

| Что | Период | Цена |
|---|---|---|
| ростер Nomad + состояния с узлов | 15 с | десятые доли секунды |
| обмер места (`sizes`, du по target) | 2 мин | секунды IO на узле, под nice |
| расход токенов (`usage`, разбор транскриптов) | 10 мин | до полутора минут по всем телам |
| живые мастера (опрос `who` в общий инбокс каждого проекта, #305) | 30 с | по две секунды ожидания ответов на проект |

Диагностики `mop server doctor` на странице нет (решение оператора 2026-09-22): она
стоила запроса к Nomad на каждого папета каждым кругом, а лечение всё равно
остаётся за `mop server doctor`; больной папет виден корзиной `sick`.

Событие на шине сдвигает быстрый круг вперёд с паузой в секунду на пачку:
после `send` папет читается занятым через секунду, а не через четверть
минуты. Смену состояния внутри сессии агент не видит, поэтому опрос остаётся
основой, а события — ускорителем и журналом.

## Корзины

Страница не разбирает текст состояния второй раз: корзину считает
`web.classify`, по тем же префиксам, по которым `doctor` назначает лечение.

| Корзина | Когда |
|---|---|
| `down` | аллокация не работает (pending, lost, queued, ошибка ростера) — спрашивать некого |
| `silent` | вид `silent` (`AGENT SILENT`): молчит узел, не папет; лечения с мастера нет |
| `free` | `state.is_free`: в клоне нет несохранённой работы |
| `sick` | вид, которому doctor назначает лечение (`state.action_for`): `HUNG`, `needs action`, `not logged in`, `login expired`, `no model quota`, `error` |
| `busy` | всё остальное, включая `waiting for input` |

Матрица проверяется без пула: `python3 tests/web.py`.

## Кто и где

Дашборд читает пул как мастер: по токену Nomad и под `service` шины. Ни того ни
другого узлам не дают, поэтому он живёт на сервере, рядом с NATS, а не на
узле; и не на машине оператора — страница нужна, когда мастер-шелл закрыт.
Роль кладёт креды в тот же каталог, откуда их читает любой мастер
(`~/.config/mop/servers/<адрес>/`, `mop/common/creds.py`), и второго способа
представиться шине у дашборда нет. Ростер, узлы и пул сборщик спрашивает у
сервиса кластера по субъекту без логина `mop.<проект>.cluster.rpc`: у машины
логина нет, и этот субъект `service` открыт намеренно, а с логином — закрыт
([BUS](BUS.md), #309). `.env` на сервер не едет: адрес сервера и
порты юнит передаёт окружением.

Операции дашборда едут субъектом проекта цели (#460): у воркера нет своего
админ-субъекта, и права NATS работают как для мастера. Журнал операций,
payload и реестр проектов — в приватном каталоге пула на сервере
(`~/.config/mop/operations/`, 0700).

Порт наружу не проброшен и проброшен быть не должен — та же логика, что у
шины на 4222 и у API Nomad на 4646: границу держит роутер. На странице видны
имена узлов, origin'ы проектов и состояния — ровно то, что показывает UI
Nomad на 4646.

## Секреты в журнале и хвосте

Публичные события и admin-хвосты чистятся одним списком (`web.py`):
credential-поля (`token`, `secret`, `password`, `proxy_key`, …) снимаются
на любом уровне вложенности (#424), в свободном тексте гасятся
bearer-значения и `ключ=значение` по тому же признанному списку слов;
произвольный текст секретом не считается, и обещать этого нельзя. Записи
полного журнала несут все поля события без credential-полей, исходный `at`
(невалидный — время получения) и отдельный `received_at`; ответы карточки
и хвоста — no-store и не логируются.

## Проверка

`mop server deploy` в конце роли ждёт `200` от `/healthz` — это «первый снимок
собран», а не «процесс запущен»: юнит в бесконечном рестарте systemd вполне
устраивает. Роль proxy затем запрашивает тот же `/healthz` с контроллера
сквозь TLS. Руками: `curl https://<сервер>/api/pool` (с самоподписанным —
`--cacert ~/.config/mop/secrets/tls.pem`).

Без пула проверяются: матрица корзин и виды (`python3 tests/web.py`),
исполнитель операций (`tests/opworker.py`), HTTP-адаптер (`tests/adminapi.py`),
инвариант безопасности (`tests/lease.py`, блок #460), вердикты общих
операций (`tests/ops.py`).

## Мастера

Реестра мастеров нет намеренно (`mop/cli/service/mcp.py`, `_masters`):
живой мастер — тот, кто отозвался на `who` в общий инбокс проекта
`mop.<проект>.master.all.inbox`; отвечает MCP-сервер mop в сессии мастера
адресом, логином, именем сессии и каталогом. Сборщик опрашивает так каждый
проект из реестра сервера (`projects.read()`, в том числе без папетов) и из
ростера, раз в 30 секунд (#305); `service` публиковать туда вправе, ответы —
в `_INBOX`. Колонка «папеты» — папеты проекта, чья аренда на логине мастера.
Закрытая сессия пропадает из списка на следующем опросе.
