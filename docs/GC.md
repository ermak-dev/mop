# Сборка мусора: место на узлах

Давление на диск лечится двумя ступенями: мягкой — сторож на узле подрезает
артефакты — и жёсткой — `mop gc` на мастере пересоздаёт свободных папетов.
Пороги: `MOP_SWEEP_FREE_MIN_GB` (60 ГБ) и `MOP_GC_FREE_MIN_GB` (25 ГБ); жёсткий
обязан быть ниже мягкого: сначала дешёвое подрезание, потом дорогой рецикл.

## Кто о чём судит

Агент отдаёт факты, вердикты выносит мастер: на ответе «свободен ли папет»
(`state.verdict`) стоит решение о диспатче, и второе место с тем же
ответом ему не нужно.

| Кто | Что делает | Чем запускается |
|---|---|---|
| узел | подметает сирот: клоны и target-каталоги без живой сессии | глагол агента `sweep`; ежечасно — `mop-doctor.timer` на сервере |
| узел | режет cargo-каталоги под мягким давлением | там же |
| мастер | решает, кого пересоздать, и делает это | `mop gc`, вручную |

## Сторож

Скрипт `deploy/roles/bus/files/pu-sweep.sh` ставится на узлы плейбуком (игра про узлы `puppet`),
а исполняет его агент узла глаголом `sweep` (ниже). Ярусы, от дешёвого к дорогому:

1. **сироты** — всегда: кандидат — папет без живой tmux-сессии, названной по
   имени джоба. Отсутствие сессии ещё не сиротство: папет на подъёме и папет
   с падающим bootstrap'ом живут без tmux часами. Поэтому снос — только когда
   в клоне нет работы; клон с несохранённым или неотправленным остаётся и
   называется в выводе. На host-узле это клоны в `~/puppets` (свой разбор
   работы в `pu-sweep.sh`); на узле с отдельными телами — ярус 0,
   `mop driver sweep`: тело сносится, только если tmux ответил «сессии нет»
   и клон пуст по `domain.holds_work` либо его нет вовсе (#346); клон с
   работой, непрочитанный клон и тело, которое не отвечает, остаются;
2. **заброшенные пути** — всегда, но не моложе `MOP_SWEEP_STALE_DAYS`;
3. **target-каталоги живых папетов** — только под давлением (свободно меньше
   `MOP_SWEEP_FREE_MIN_GB`), размер ограничен `MOP_SWEEP_MAX_TARGET`
   (cargo-sweep из `sandbox.yaml`; без него ярус деградирует мягко).

Предохранители против сноса всего узла из-за недоступного tmux или
несмонтированного ecryptfs-дома — в самом скрипте. Сторож видит и старые корни
`~/wk/wk-*` (наследие переезда пула): снять глоб можно, когда те опустеют.
Пороги — узловые настройки (`config.NODE_SCOPED`): значения живут в
`config.SETTINGS` в одном месте, `mop server deploy` кладёт их в `node.env`.

Скрипт зовёт агент узла глаголом `sweep` (#358): `mop doctor disk`
спрашивает каждый готовый узел всухую — что сторож снёс бы и кто под давлением,
— а `--fix` метёт по-настоящему. Пороги агент берёт из `node.env`, а не из
запроса: сколько места держать свободным, решает машина.

По расписанию doctor запускает сервер (#359): `mop-doctor.timer` ежечасно
поднимает oneshot `mop-doctor.service` — `mop doctor --fix --safe`, то есть
подметание и логин из реестра, без рестартов и `/model`; вывод —
`journalctl -u mop-doctor`. Пропущенное за простоем не догоняется
(`Persistent=false`). Это единственный триггер подметания: Nomad periodic
`pu-cleanup` (sysbatch) снят (#361) — прогон deploy снимает живой джоб с его
периодическими детьми и отказывает, если что-то с этим префиксом осталось.
С ним ушла и его ловушка: sysbatch-ребёнок, застрявший pending на недоступном
узле, с `prohibit_overlap` клинил расписание для всех узлов.

## Место папета

Клон плюс его target-каталог:

    ~/puppets/<имя>            puppets.clone_dir(name)
    ~/.cache/target-<имя>     врапер: TARGET_DIR / CARGO_TARGET_DIR

Оба пути заводит ядро (врапер живёт в спеке джоба), поэтому рецикл ничего не
знает о проекте. Второй — почти весь объём.

## Рецикл: восстановление из git, а не переклонирование

`mop recycle <имя>` и `mop gc` зовут `puppets.recycle`, порядок обязателен:

    1. nomad job stop <имя>
    2. дождаться терминального статуса аллокации
    3. wipe через шину: git reset --hard + git clean -xdff (щадит MOP_PUPPET_SEED) + rm -rf target
    4. nomad job run (перерегистрация спеки из Meta джоба)

Останов первым не перестраховка: между «мастер решил, что папет свободен» и
сносом папету успевает прилететь задача (`mop send` идёт мимо мастера), и
остановленный джоб — единственное состояние, в котором сессии гарантированно
нет. Перерегистрация, а не рестарт аллокации: врапер живёт в спеке джоба.

Рабочая копия восстанавливается из git на месте: reset откатывает
отслеживаемое, `clean -xdff` выметает и untracked, и игнорируемое — но
исключения берутся из `MOP_PUPPET_SEED`: тот же список, которым врапер
сеет `.env*` и `.providers` из `~/puppet-env`, так что ключи проекта
переживают сброс, а список живёт в одном месте.

Глаголы агента, замешанные в это:

* `wipe` — проектовый и именной; отказывает при живой tmux-сессии («сессия жива»
  — факт, и снос под живой недопустим);
* `disk` — узловой, `admin`: `df` по `$HOME`, `{path, free_gb, total_gb}`;
* `sizes` — проектовый, `.rpc`: место папетов пачкой, `du` по спросу; отдельный
  глагол, а не поле в `states`, чтобы медленный обмер не читался как «агент
  молчит».

## `mop gc [--dry]`

Собрать `disk` по узлам со папетами → найти узлы ниже `MOP_GC_FREE_MIN_GB` →
на каждом рециклить свободных папетов (`state.is_free` по виду вердикта: «в клоне нет
несохранённой работы», не «сессия молчит»), от самого тесного узла и самого
жирного папета, не больше `MOP_GC_MAX_PER_RUN` за прогон. `--dry` показывает
план без исполнения. Запускать оператором, не в мастер-шелле: давление узла и
глагол `disk` — про все проекты сразу.

## Проверка

Матрица состояний и правило `is_free` — `python3 tests/state.py`, без пула.
Остальное (отказ `wipe` под живой сессией, переживание перерегистрации,
совпадение `--dry` с боевым прогоном) проверяется только на живом пуле.
